CONNEXION À L’INDEXER

Source Wazuh

Les groupes d’agents sont détectés dans les alertes et apparaissent automatiquement dans les filtres du dashboard.

La configuration, y compris le mot de passe Wazuh, est conservée dans la base SQLite locale du service.

Saisissez l’adresse de l’Indexer, pas celle du Manager ou du Dashboard. Format habituel : https://nom-ou-ip:9200, sans chemin d’index. Sur le serveur, vérifiez network.host et http.port dans /etc/wazuh-indexer/opensearch.yml.

Pour tester depuis PowerShell, remplacez l’hôte et l’utilisateur. curl.exe demandera le mot de passe :

curl.exe -u "UTILISATEUR" "https://INDEXER:9200"

Utilisez un compte dédié en lecture seule, autorisé à rechercher dans les index des alertes et de l’inventaire des vulnérabilités. Demandez-le à l’administrateur Wazuh. Sur le serveur Indexer, les noms de comptes se trouvent dans /etc/wazuh-indexer/opensearch-security/internal_users.yml :

sudo grep -E '^[[:space:]]*[A-Za-z0-9_.-]+:' /etc/wazuh-indexer/opensearch-security/internal_users.yml

Mot de passe du compte Indexer ci-dessus. Pour une configuration existante, laissez ce champ vide pour conserver le mot de passe enregistré. Il ne peut pas être retrouvé depuis le fichier des utilisateurs, car il y est stocké sous forme de hash ; demandez sa réinitialisation à l’administrateur. Ne le mettez pas dans une commande ni dans un message.

À cocher seulement si le certificat est auto-signé ou signé par une autorité non approuvée. Cela désactive sa vérification et expose la connexion à une interception. La meilleure solution est d’installer le certificat de l’autorité dans le magasin de certificats de la machine qui exécute ce service.

À activer uniquement si le certificat est auto-signé ou non reconnu. Cela réduit la sécurité de la connexion.

La valeur par défaut wazuh-alerts-* convient à la plupart des installations. Dans Wazuh Dashboard, ouvrez Outils de développement et exécutez :

GET _cat/indices/wazuh-alerts-*?v

Le compte configuré doit avoir le droit de lecture sur ces index.

La valeur par défaut wazuh-states-vulnerabilities-* correspond à l’inventaire courant de Wazuh. Le compte doit avoir le droit de lecture sur ces index. Le test d’enregistrement vérifie l’index des alertes ; lancez une recherche d’agent pour valider cet accès.

Nombre maximal d’alertes lues à chaque contrôle. Gardez 100 pour commencer ; augmentez si le volume est élevé. La limite acceptée est de 1 à 1000.

ACTION IRRÉVERSIBLE

Vider toutes les alertes

Cette action supprime définitivement toutes les alertes de tous les clients, ainsi que les incidents et analyses associés. La base SQLite sera compactée. Cette action est réservée aux administrateurs et ne peut pas être annulée.
